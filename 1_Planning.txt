# Day 1 – RAG Architecture (Hiểu chứ không phải thuộc lòng)

## Bạn phải làm được:

Vẽ được pipeline:

```
Document → Chunk → Embedding → Vector DB
Query → Embed → Retrieve → LLM → Answer
```

## Thực hành:

* Lấy 1 hợp đồng thuê nhà PDF
* Parse ra text
* Chia chunk
* Lưu FAISS / Chroma
* Query: “What is the termination clause?”

## Phải trả lời được:

* RAG giải quyết vấn đề gì?
* Vì sao không đưa nguyên document vào context?
* Context window limit ảnh hưởng ra sao?

Bước 3 – Chunking

Cài:

pip install langchain

Hoặc tự viết splitter.

Test 3 loại chunk:

500 characters

1000 characters

Overlap 100

In ra để xem.

Đây là lúc bạn bắt đầu suy nghĩ như engineer.

Bước 4 – Embedding

Dùng:

sentence-transformers (local)

Hoặc OpenAI text-embedding-3-small

Embedding model phải hiểu semantic, không phải TF-IDF.

Bước 5 – Vector DB

Cài:

pip install faiss-cpu

Lưu embedding vào FAISS.

Hiểu:

FAISS dùng approximate nearest neighbor

Cosine similarity = normalized dot product

Bước 6 – Query

Query:

"What is the termination clause?"

Flow:

Embed query

Search top-k = 3

Concatenate chunk

Pass vào LLM

# 🧠 Giờ tóm lại Tuần 1 bạn cần hiểu gì?

## 1. Agent là gì?

LLM + khả năng:

* Lập kế hoạch
* Gọi tool
* Quyết định bước tiếp theo

Không phải chatbot fancy.

---

## 2. Khi nào dùng agent thay workflow cứng?

Dùng agent khi:

* Task không xác định trước step
* Có nhiều tool
* Cần reasoning linh hoạt

Không dùng agent khi:

* Pipeline cố định
* Logic rõ ràng
* Cần deterministic 100%

---

## 3. Ưu nhược điểm Agentic System

### Ưu:

* Linh hoạt
* Khả năng xử lý task phức tạp
* Dễ mở rộng tool

### Nhược:

* Khó debug
* Không deterministic
* Cost cao
* Dễ loop
* Hard to monitor

---

## 4. Reliability vấn đề ở đâu?

* Hallucination
* Tool misuse
* Infinite loop
* Context drift
* Không bám retrieval

Và đây là phần phỏng vấn thích hỏi nhất.
